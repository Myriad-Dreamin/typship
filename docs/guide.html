typship 指南：Pack 规范与架构参考

本指南对应 typship 主线（crates/typship 与 crates/typship-pack）的实际实现。

1. Pack 概念与设计边界（A Concept Weaker than Package）

正式的 Typst Package 必须包含符合规范的 typst.toml（含 name、version、entrypoints）并具有 @namespace/name:version 身份。而 Pack 是比 Package 更弱的抽象：任何承载 Typst 内容的目录树或归档流，无论是否包含 typst.toml，都是一个 Pack。解包或浅克隆时，find_pack_root 会沿最多 3 层单子目录链查找 typst.toml；若不存在清单，则保留原始目录树结构整体搬运。

3. 解包安全、确定性归档与超时红线

Typst 对齐解包校验：仅接受普通文件与目录成员；严拒绝对路径、.. 组件、非 UTF-8 成员名以及任何符号链接/设备节点。物理路径防嵌套：ensure_distinct 将源与目标解析为物理路径后按组件比较，拒绝自我嵌套。网络与 Git 超时：HTTP 10s 连接 / 120s 总超时（仅对传输错误、429、5xx 重试 3 次）；git 子进程 120s 看门狗超时整树终止。

4. 双 Crate 架构

crates/typship 负责命令行解析（基于 palc）、init 清单生成与 download 缓存入口；crates/typship-pack 独立封装 Named Pack 的源/目标识别（source.rs / dest.rs）、传输与解包打包（transport.rs）、copy/link（copy.rs）及 HTTP/GitHub 交互。
